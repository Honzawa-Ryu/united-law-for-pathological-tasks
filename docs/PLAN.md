# 計画: World Snapshot Models (WSM) を病理画像で試す

最終更新: 2026-11-21（計画段階。実験は未着手）

## 目的
1. WSM（arXiv:2611.24917「Unified Law for Visual Tasks」）が H&E 病理画像で実用になるかを、BRACS などの公開ベンチで確かめる。
2. 実用になりそうなら、WSI 全体の診断へ広げる方法を検討する。

## 判定したい問い
同じデータ・同じ分割で、「UNI + 軽量ヘッド」に対して WSM のトンネルに次のいずれかの利点があるか。
- 少数ショット（10〜500 枚）での精度
- 1 つの骨格で複数タスクを足せること（セグメンテーション + 分類など）
- 局在（病変マップ）の質

精度が同等でも、推論が桁違いに遅く上の利点も無ければ撤退する。

## 段階

### 着手前: ライセンスと利用条件（2026-11-21 確認済み）
- WSM（コード・重み）: Rutgers 非商用研究ライセンス。学術・研究・個人の非商用利用が可。改変物や重みの再配布は著作権表示を残せば可。入力データへの制限、論文発表への制限、特許条項、終了条項は本文に無い。商用は Rutgers の別途許諾が必要。
- BCSS: データは CC0。登録不要（Google Drive またはスクリプトで取得、0.25 MPP）。22 クラス、画素値 0 は「ROI 外」で損失から除く。推奨分割は grand-challenge のページにあり未確認。
- BRACS: CC BY-NC 4.0。**実名での利用登録が必要**（匿名不可）。547 WSI / 189 患者、ROI 4539 枚（train 3657 / val 312 / test 570）、40 倍（0.25 µm/px）、ROI は PNG で 4000 px 四方を超えるものもある。7 クラス: N, PB, UDH, FEA, ADH, DCIS, IC。
- Bayer 注釈: 利用者の判断で「必要なら使ってよい」。ただしまず疾患病理（BCSS / BRACS）で見る。Phase 3 まで使わない。

### 決定事項（2026-11-21）
- 順序はどちらでもよいとのことなので、登録不要ですぐ取れる BCSS を先に行い、BRACS は登録が済み次第取得する。
- 当面の対象は疾患病理（ヒト）。TG-GATEs / Bayer 注釈は WSI 拡張の段階で使う。

### Phase 0: 動くか・情報が残るか（x86 / A6000、目安 1〜2 日）
- 重み取得（`continued_training_materials` を除く）。公開タスク（RGB→depth）の推論を再現。
- 計測: ピーク VRAM、秒/更新、秒/タイル、チェックポイントからの再開（4 時間枠が前提）。
- 学習なしで測れる関門 2 つ:
  - 入力側: H&E を FLUX.2 VAE に往復させ、往復前後で UNI 埋め込みの類似度と核検出の再現率を比べる（PSNR だけでは判定しない）。
  - 出力側: 正解パレットマスクを VAE に往復させ、色復号後の mIoU と境界 F1 を測る。
- 少数枚で過学習できるかを確認。
- 関門の扱い: 核が崩れるなら核タスクだけ保留。組織レベルのマスクも崩れるなら全体を中止。

### Phase 0.5: 骨格の切り分け（数時間）
- 凍結 FLUX.2 の中間特徴 + 軽量デコーダを、UNI / DINOv2 + 同じデコーダと比べる。
- 目的: 「骨格に病理の表現が無い」のか「トンネルの問題」なのか、「生成か判別か」と「病理事前学習か自然画像事前学習か」を分ける。

### Phase 1: 組織セグメンテーション（BCSS）
- 100 タイルで学習曲線 → 見込みがあれば 500 タイル・複数シード → 全量。
- 比較: UNI + 軽量デコーダ、DINOv2 + 軽量デコーダ、凍結 FLUX 特徴 + 軽量デコーダ。
- 指標: mIoU、境界 F1、秒/タイル。許容する mIoU 差は学習前に決めて記録する。
- 核（PanNuke / CoNSeP）は Phase 0 の関門を通った場合のみ、その後に行う。

### Phase 2: BRACS ROI 7 クラス分類
- データ取得は利用登録（利用者本人）が済み次第。
- 第一候補: 著者の分類枝のクラス別スコアをタイル単位で取り、ROI ラベルで損失を取って集約（平均 / attention pooling）。
- 対照: 全面を単色パレットで塗る目標画像 + 多数決（局所病変が埋もれるので主案にはしない）。
- 比較: 公式分割で UNI / CONCH の線形プローブ（入力視野を揃える）。既報値（HACT-Net など）は分割と評価単位が一致する場合のみ参照。
- 指標: macro-F1、クラス別再現率（特に FEA / ADH / DCIS）。

### Phase 3: WSI 全体（TG-GATEs ラット肝）
Phase 1 を通過した場合のみ。まず秒/タイルの実測から 1 WSI の所要時間を出す。
- 案1 全タイル: 病変マップ → 面積率などを既存の UNI + MIL に足したときの増分を測る。単純で比較しやすいが、推論時間が最大の制約。
- 案2 階層型: 低倍率で粗い病変マップ → 上位領域だけ高倍率で精密化。計算は軽いが、低倍率で見えない微小病変は拾えない。所見を「低倍率で見える / 高倍率が必要」に分けて評価する。
- 案3 特徴グリッド: タイル特徴のグリッドを 1 枚の「WSI スナップショット」として入れる。伸びしろは大きいが、RGB 用 VAE に高次元特徴は入らず改造が大きい。探索枠。
- 進め方: 注釈の厚い所見を 1 つ選び、案1 を基準に、候補抽出の再現率を測ってから案2 を入れる。

## 評価の決まりごと
- 分割はヒトなら患者、ラットなら個体単位。未知化合物への一般化を言うなら化合物も分ける。
- 少数ショットはタイル数と由来スライド数を併記する。
- 生成は初期ノイズで揺れるので、推論回数（1 回 / N 回平均）を固定し、計算量込みで比べる。
- パレットの色設計と復号しきい値は検証セットで固定する。

## 計算資源
- Phase 0〜1 は Creator（x86 / A6000 48GB）。Grace（ARM）は環境構築の手間が大きいので後回し。
- latent シャードは大きい（FLUX.2 VAE は 32ch）。置く前に `du` で量を見積もり、共通置き場に 1 つだけ置く。
- ジョブは 4 時間枠で再開できる形にする。
