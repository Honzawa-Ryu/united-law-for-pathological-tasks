# 相談: World Snapshot Models (WSM, arXiv:2611.24917) を病理画像に試す計画の素案

## 前提（公開情報から確認できたこと）
- WSM v1 = 凍結した FLUX.2 Klein 4B（Apache 2.0）+ タスクごとの低ランク「トンネル」(約12.5M パラメータ)。全視覚タスクを「画像→画像の生成」に書き換える。
- 新タスクは (1) 条件画像と目標画像を VAE latent にしてシャード化 (2) custom json に Channel_Head を追加 (3) トンネルだけ学習、で追加できる。著者主張では数百サンプル・A100 1枚で数時間。推論は10ステップ程度。
- 分類は「領域を生成 + 軽量分類枝がパレット色を割り当てる（学習プロトタイプとのコサイン類似度）」、セグメンテーションは意味パレット画像、検出は塗りつぶし疑似色領域。
- 学習データは AVIS / ShapeNetSem / MatSynth など自然・合成画像。医療・病理タスクの報告は見当たらない。ImageNet/ADE20K/COCO の数値も未確認。
- コードと重みは Rutgers 非商用研究ライセンス。VRAM 要件は未記載（512x512 らしい）。
- 手元の計算資源: Slurm、1ノード1GPU（RTX A6000 48GB 級、x86）と GH200(ARM)。1ジョブ最長4時間枠が基本、通常枠は同時2ノード。
- 手元のデータ: TG-GATEs ラット肝 WSI（多数）、Bayer の病変注釈、UNI 等の病理基盤モデルの埋め込み基盤。BRACS は未取得。

## 目的
1. WSM が病理画像（H&E）で実用になるかを、BRACS など公開ベンチで確かめる。
2. 可能なら WSI 全体の診断へ広げる方法を考える。

## 素案
- Phase 0: 再現確認。重み取得、A6000 で公開タスク（RGB→depth 等）の推論と、小さな custom トンネル学習が動くか、VRAM と時間を測る。FLUX.2 VAE が H&E を再構成できるか（PSNR/細胞核の保存）も測る。
- Phase 1: 密な予測（WSM が得意なはずの形）。核セグメンテーション/分類（PanNuke, CoNSeP）、組織セグメンテーション（BCSS など）をパレット画像として学習。比較は HoVer-Net/CellViT、UNI+線形デコーダ等。サンプル数を 100/500/全量と振り、少数ショット効率を見る。
- Phase 2: BRACS ROI 7クラス分類。案A: ROIをタイルにし全面を単色パレットで塗る目標画像→多数決。案B: 著者の分類枝をそのまま使う。比較は UNI/CONCH 線形プローブ、HACT-Net など既報値。
- Phase 3: WSI への拡張の検討。案1: タイル単位で病変マップを生成→集約（MIL）。案2: サムネイル/低倍率画像を条件に粗い病変マップを生成し、高倍率で精密化する階層型。案3: 病理基盤モデルの特徴マップを .wsg の追加チャンネルとして入れる。TG-GATEs の所見ラベルで検証。
- 中止基準: Phase 0 で VAE 再構成が核形態を壊す、または Phase 1 で UNI+軽量デコーダに大差で負け少数ショットの利点も無ければ撤退。

## 聞きたいこと
1. この順序と中止基準は妥当か。もっと安く早く「実用になるか」を判定できる実験はあるか。
2. 生成モデルで分類/セグメンテーションをする既存研究（病理を含む）で、必ず比較・引用すべきもの。
3. BRACS を最初にやるべきか、密予測から入るべきか。BRACS 分類を生成で解く最良の定式化は。
4. WSI 全体への拡張で最も筋の良い案と、落とし穴。
5. 見落としているリスク（評価の罠、ライセンス、染色ドメインシフト、8倍 VAE の解像度損失など）。
簡潔に、箇条書きで、根拠の弱い点は弱いと明記して答えてください。ファイルの変更やコマンド実行は不要です。
