### 1. 順序と中止基準の妥当性・より安く早い判定実験

- **大枠の順序（Phase 0 → 密予測 → ROI分類 → WSI）は妥当だが、2点修正を推奨**
  - **Phase 0 に「マスク（パレット画像）の VAE 往復復元テスト」を追加すべき**: WSM は入力（H&E）だけでなく**出力（離散パレット画像）も VAE latent 経由**。学習ゼロ・数分で「細密マスク（特に 5〜15px の密集核）が VAE 往復で色滲み・核癒合しないか」を確認でき、最も安い早期ゲートになる。
  - **H&E 再構成の評価指標は PSNR だけでは不十分**: 背景の淡い領域で PSNR が高く出やすいため、「元画像 vs VAE 再構成画像」に既存の **UNI 埋め込み（コサイン類似度・線形プローブ精度差）や HoVer-Net/CellViT（核検出 F1 低下）**を通して診断情報の保存を測るべき。
  - **Phase 1 の初手は PanNuke（核インスタンス）ではなく組織・病変領域セグメンテーションにすべき**: 核は「接触核のインスタンス分離」が本質であり、単なる意味パレット生成では WSM に最も不利。**BCSS や手元の TG-GATEs + Bayer 病変注釈（512×512 パッチ）**の方がデータ取得待ちゼロかつ WSM の得意形に素直に合う。
- **さらに安く早い判定実験（Phase 0.5 案）**
  - **凍結 FLUX.2 中間特徴の線形/軽量プローブ診断**: トンネル学習が重い・不調な場合に備え、FLUX.2 Klein 4B の中間特徴（1ステップノイズ付加・Baranchuk et al. 方式）に軽量デコーダを載せて UNI / DINOv2 と比較する。これにより「**凍結バックボーン自体に病理表現力がないのか、トンネル設計の問題なのか**」を数十分〜数時間で切り分けられる。
- **中止基準の補強**
  - 現状の基準に加え、**推論コスト差（4B DiT × 10ステップ vs UNI 1フォワード）**を明示的に織り込むべき。精度が UNI+線形と同等でも推論が 10〜50倍遅ければ WSI 実用は厳しいため、**「少ショット（例: 10〜50枚）での優位性」「多タスク統一（セグ+染色正規化等）」「不確実性推定」のいずれかが明確に示せなければ撤退**とするのが現実的。
  - ※ **根拠弱**: 著者の「数百サンプル・A100 1枚で数時間」は自然・合成画像での主張であり、強いドメイン外（H&E）で 12.5M パラメータの低ランク経路だけで収束するか・4時間 Slurm 枠に収まるかは未検証。

### 2. 必ず比較・引用すべき既存研究

- **汎用ビジョン：生成モデルによる密予測・タスク統一（WSM の直接の先行系譜）**
  - **Painter / SegGPT** (Wang et al., 2023): 「視覚タスクを画像の色塗り（image-to-image）へ統一」の原点。
  - **Marigold** (Ke et al., CVPR 2024): 事前学習拡散モデルの密予測・少データ汎化を示した起点。
  - **Lotus** (He et al.) / **GenPercept** (Xu et al., ICLR 2025): **最重要の対照軸**。「密予測では多ステップのノイズ予測は不要・有害で、**1ステップ直接アノテーション予測**の方が高精度かつ高速」と主張。WSM の 10ステップ生成の必然性を問う比較相手になる。
  - **DDP** (Ji et al., ICCV 2023) / **Pix2Seq・Pix2Seq-D** (Chen et al.) / **Baranchuk et al.** (ICLR 2022) / **DatasetDM** (NeurIPS 2023): 拡散による密予測・特徴抽出の定番引用。
- **汎用ビジョン：生成モデルによる分類**
  - **Diffusion Classifier** (Li et al., ICCV 2023): 拡散モデルの条件付きノイズ予測誤差（ベイズ尤度）でゼロショット分類（ただしクラス数×ステップ数で計算が重い）。
- **医療・病理：拡散モデルによるセグメンテーション・表現利用**
  - **MedSegDiff / MedSegDiff-V2** (Wu et al., 2023/2024)、**SegDiff** (Amit et al.)、**Diff-UNet** (Xing et al.): 医療拡散セグメンテーションの標準引用（放射線中心）。
  - **PathSegDiff** (2025/2026 頃): 病理 LDM 特徴による BCSS/GlaS セグメンテーション（※ **根拠弱**: 比較的新しく標準ベンチとしての定着度は限定的）。
- **病理の生成基盤モデル（ドメイン事前学習との比較・WSI 拡張の参考）**
  - **PixCell** (2025): 大規模 H&E 学習の病理生成基盤モデル（仮想染色・合成拡張）。
  - **PathLDM** (WACV 2024) / **ZoomLDM** (2025): テキスト条件付き病理 LDM、および**多倍率・階層的 WSI 生成**（Phase 3 案2の直接の先行研究）。
- **実験上必須の判別ベースライン**
  - **病理基盤**: UNI / CONCH（+ 線形 / Mask2Former 等）、HoVer-Net / CellViT（核）。
  - **自然画像判別基盤（交絡切り分け用）**: **DINOv2** + 軽量デコーダ（後述のリスク参照）。

### 3. BRACS を最初にやるべきか vs 密予測から入るべきか／BRACS の最良定式化

- **密予測から入るべき（BRACS を最初にするのは非推奨）**
  - BRACS は未取得であり、かつ純粋な ROI 7クラス分類は「画像→画像」の生成コストに見合いにくい。
  - BRACS の ROI はサイズ・アスペクト比が不均一で、7クラス鑑別（特に FEA / ADH / DCIS の境界）には**低倍率の腺管構築＋高倍率の細胞異型**の両方が必要。512×512 固定入力に押し込むと手法検証以前に前処理で詰まりやすい。
- **BRACS を WSM で解く場合の定式化比較**
  - **案A（タイル全面単色塗り→多数決）は非推奨**: 病変は ROI 内の一部に局在することが多く、全タイルへ ROI ラベルを貼ると強いラベルノイズになる。また多数決は少数の悪性（ADH/DCIS）タイルを良性タイルが押し潰す。
  - **案B（著者の分類枝をそのまま使う）の方が妥当だが工夫が必要**: そのまま単一 512×512 へリサイズすると高倍率情報が潰れ、ROI 内に正常組織と病変が混在すると「どの領域を前景として分類するか」が曖昧になりやすい（※ **根拠弱**: WSM 分類枝の多組織混在時の挙動はコード・論文詳細未確認）。
  - **推奨する現実的な定式化（折衷案）**:
    1. タイルごとにパレット画像へデコードして多数決するのではなく、**分類枝が出すクラス別コサイン類似度（ロジット）をタイル単位で取得し、Attention-MIL または重症度順 Max-pooling で ROI 集約**する。
    2. あるいは「低倍率全体リサイズ画像＋高倍率クロップ」をマルチチャンネル入力にして案B を適用する。

### 4. WSI 全体への拡張：最も筋の良い案と落とし穴

- **最も実用・計算コストのバランスが良い案：案2（階層型：低倍率→高倍率）**
  - **理由**: TG-GATEs のラット肝所見（壊死・脂肪化・線維化・肥大・胆管増生など）の多くは低倍率（1.25x〜5x）でも構造変化の当たりが付きやすく、低倍率数枚で粗い病変マップを生成→高スコア領域 Top-K のみ高倍率で精密化すれば、計算量を 1/50〜1/100 に抑えられる。
  - **落とし穴**: **微小病変（単細胞壊死、小炎症巣、核分裂像など）は低倍率で完全に見落とされ偽陰性（Recall 崩壊）**になる。所見タイプを「低倍率可視／高倍率必須」で層別評価することが不可欠。またタイル境界のつなぎ目（シーム）の不連続が起きやすい。
- **案1（全タイル病変マップ生成→MIL）の評価と落とし穴**
  - **最大の落とし穴は推論時間**: 1 WSI = 5,000〜20,000 タイルに対し 4B DiT × 10ステップを全走査すると、1スライドあたり数十分〜数時間かかり、TG-GATEs 大量検証が Slurm 4時間枠で破綻しやすい（※ **根拠弱**: A6000 での実測スループットは未計測）。
  - また「MIL で集約する」なら画像にデコードせず中間特徴を渡す方が自然で、その場合「UNI + MIL に対して生成モデルを使う理由」が薄れる。
- **案3（UNI 特徴マップを `.wsg` 追加チャンネル入力）の評価と落とし穴**
  - **最も研究的な伸びしろがある案**: 凍結 FLUX.2 の「病理知識不足」を補える唯一の設計。さらに **WSI 全体のタイル特徴グリッド（例: 64×64〜512×512）自体を 1枚の「WSI スナップショット」として入力**できれば、1回の生成でスライド全体の病変マップを出せる可能性がある。
  - **落とし穴**: WSM の入力は FLUX.2 VAE を通す前提だが、**高次元 UNI 特徴（例: 1024ch）はそのまま RGB 用 VAE に入らない**。PCA で 3ch 化すると情報が削げ、逆に VAE をバイパスして DiT の latent 空間へ直接射影するなら WSM 標準の `.wsg` / `Channel_Head` を大幅改造する必要があり、凍結 DiT の分布外になって学習が不安定になりやすい（※ **根拠弱**: 実装改造コストはコード未確認のため推測）。

### 5. 見落としているリスク

- **ライセンス・権利の衝突リスク（最優先確認）**
  - WSM のコード・重みは **Rutgers 非商用研究ライセンス**。手元の **Bayer 病変注釈** が企業共同研究・社内活用・商用利用条件を含む場合、非商用条項に抵触する恐れが高い（UNI 等の基盤モデル側にも非商用制限がある場合がある）。着手前に WSM の LICENSE 全文とデータ契約の整合性を確認すべき（※ FLUX.2 Klein 4B 本体は Apache 2.0 なので、最悪トンネル部分だけクリーンルーム実装する選択肢はある）。
- **VAE 8倍圧縮＋DiT 2×2 パッチ化（実質 16×16px 格子）とパレット量子化の罠**
  - FLUX.2 VAE は 32ch と高表現力だが空間 8倍圧縮であり、さらに DiT 内部で 2×2 パッチ化（128ch・**1トークン = 16×16px**）される。20x〜40x の核（直径 10〜30px）は 1〜2 トークン幅しかなく微細境界が潰れやすい。
  - RGB パレット生成→最近傍色マッピング方式では、**クラス A と B の境界ピクセルが中間色に滲み、無関係なクラス C に誤分類される**罠が頻発する（RGB 空間で最大距離になる色設計、または著者の分類枝の併用が必須）。
- **評価の罠（リーク・交絡・確率的揺らぎ）**
  - **スライド／個体・施設単位の分割漏れ**: 同一 WSI や同一ラット個体・同一試験のタイルが train/test に跨ぐと、生成モデルが染色・背景テクスチャを記憶して精度が過大評価される。
  - **事前学習ドメインの交絡**: 病理事前学習済みの UNI と自然画像事前学習の WSM を比較するだけでは「生成 vs 判別」なのか「病理事前学習 vs 自然画像事前学習」なのか区別できない。**DINOv2（自然画像判別基盤）**を必ず対照に入れるべき。
  - **推論の確率的揺らぎ**: 初期ノイズ依存で出力が揺れるため、1回推論か N 回アンサンブルかを固定し、計算量込みで公平比較する必要がある。
- **染色ドメインシフトと種差・臓器差**
  - H&E は RGB 空間のごく狭い領域（紫〜桃）に集中し、施設・スキャナ間の染色差が大きい。12.5M の軽量トンネルだけで染色シフトに耐えられるかは未検証（※ **根拠弱**）。
  - ヒト腫瘍（BRACS/PanNuke/BCSS）とラット肝毒性病理（TG-GATEs）は形態・所見体系が大きく異なるため、Phase 1 の結果がそのまま Phase 3 へ外挿できるとは限らない。
- **計算インフラ・ストレージの罠（Slurm 4h 枠・A6000・GH200）**
  - **VRAM 48GB の制約**: FLUX.2 Klein 4B（bf16 約 8GB）＋条件/目標の複数 latent＋勾配・Optimizer で 48GB が逼迫しやすい。事前 latent シャード化（学習時 VAE オフロード）、`bf16`、`gradient_checkpointing`、および **4時間枠用の自動チェックポイント再開**を Phase 0 で必須確認（※ **根拠弱**: 必要 VRAM 実測値は未公表）。
  - **シャード容量の肥大**: FLUX.2 VAE は **32ch**（SD の 4ch の 8倍）なので、512×512 ペア 1組（条件+目標, bf16）で約 512KB。100万タイルをシャード化すると ~500GB〜数TB 規模になる。
  - **GH200 (ARM/aarch64)**: OpenSlide / FlashAttention / 各種 CUDA 拡張のビルドで時間を溶かしやすいため、Phase 0〜1 は **x86 + A6000** で回し、GH200 は大規模実験が確定してから投入するのが安全。

### 推奨する最小修正ルート（まとめ）
1. **着手前**: WSM（Rutgers 非商用）× Bayer 注釈・研究目的のライセンス整合を確認。
2. **Phase 0（1〜2日・x86 A6000）**: 再現・VRAM/時間計測に加え、**H&E 再構成（UNI/HoVer-Net 精度維持）＋ 離散パレットマスク往復復元**を最優先ゲートに置く。
3. **Phase 0.5〜1（密予測・領域ベース）**: PanNuke より先に **BCSS または手元 TG-GATEs/Bayer 病変マスク**で検証。ベースラインは **UNI + DINOv2 + 軽量デコーダ**、少ショット（10/50/200/全量）と推論時間込みで撤退判定。
4. **Phase 2〜3**: Phase 1 を通過した場合のみ、BRACS は「分類枝ロジット＋MIL集約」で検証し、WSI 拡張は **案2（低倍率→高倍率の階層型・所見層別評価）**を主軸、余裕があれば **案3（WSI 特徴グリッドのスナップショット化）**を探索。
